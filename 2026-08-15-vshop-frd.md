# Vshop Functional Requirements Document (FRD)

## 1. Pendahuluan

Dokumen ini menjelaskan persyaratan fungsional yang harus dipenuhi oleh Vshop. Semua fungsi tercantum dalam kategori MVP. Setiap fungsi berisi deskripsi, ucapan alur, data yang terpengaruh, dan edge cases yang relevan.

## 2. Persyaratan Umum

### 2.1 Teknologi Dasar
- Framework Next.js (App Router, Server Components, Route Handlers).
- TypeScript strict dengan tipe yang ketat.
- Tailwind CSS untuk styling responsif.
- Supabase sebagai backend (Auth, PostgreSQL, RLS, Storage).
- Midtrans sebagai gateway pembayaran (sandbox untuk development).

### 2.2 Prinsip Arsitektur
- Semua operasi bisnis (hitung harga, validasi stok) dilakukan di server-side.
- Client hanya bertanggung jawab menampilkan UI dan mengumpulkan input.
- Semua state mutations melalui API atau Supabase client yang aman.

## 3. Fitur Fungsional

### 3.1 Fitur Autentikasi

#### 3.1.1 Register
- **Deskripsi**: Pengunjung dapat membuat akun baru.
- **Ucapan Alur**:
  - Halaman register menampilkan form dengan field nama, email, password.
  - Setelah submit, panggil `supabase.auth.signUp`.
  - Jika sukses, redirect ke halaman login dengan pesan konfirmasi.
- **Data Terpengaruh**: Tabel `profiles` (full_name, role = customer, phone).
- **Edge Cases**:
  - Email sudah terdaftar → pesan error jelas.
  - Password kurang panjang → validasi client + server.
  - Server error → pesan umum tanpa bocor informasi akun.

#### 3.1.2 Login
- **Deskripsi**: Customer dapat masuk ke sistem.
- **Ucapan Alur**:
  - Form dengan email + password.
  - Panggil `supabase.auth.signInWithPassword`.
  - Setelah sukses, redirect ke halaman yang diminta (dashboard atau checkout).
- **Data Terpengaruh**: Session Supabase + tabel `profiles`.
- **Edge Cases**:
  - Akun belum diverifikasi → pesan khusus.
  - Password salah → pesan aman.
  - 2FA tidak didukung pada MVP.

#### 3.1.3 Logout
- **Deskripsi**: Customer dapat keluar dari akun.
- **Ucapan Alur**:
  - Tombol logout di header.
  - Panggil `supabase.auth.signOut`.
  - Clear session client dan redirect ke home.
- **Data Terpengaruh**: Session Supabase.

#### 3.1.4 Reset Password
- **Deskripsi**: Customer dapat meminta link reset password.
- **Ucapan Alur**:
  - Halaman reset password dengan email.
  - Panggil `supabase.auth.resetPasswordForEmail`.
  - Kirim link ke email (template Supabase default atau custom).
- **Edge Cases**:
  - Email tidak terdaftar → tidak bocorkan.
  - Link expired → redirect dengan error.

#### 3.1.5 Role Access
- **Deskripsi**: Hanya admin yang dapat mengakses route `/admin/*`.
- **Ucapan Alur**:
  - Middleware route handler memeriksa session dan role.
  - Customer mencoba akses `/admin` → redirect ke login dengan pesan forbidden.

### 3.2 Fitur Katalog Produk

#### 3.2.1 Tampilan Katalog
- **Deskripsi**: Menampilkan daftar produk aktif dengan filter.
- **Ucapan Alur**:
  - Load `GET /api/products` dengan query `?q=search&category=...&sort=price`.
  - Tampilkan grid produk dengan gambar, nama, harga, tombol add-to-cart.
- **Data Terpengaruh**: Tabel `products` (hanya `status=active`).
- **Edge Cases**:
  - Tidak ada produk → tampil placeholder.
  - Filter tidak mengubah hasil (stok nol).

#### 3.2.2 Detail Produk
- **Deskripsi**: Menampilkan informasi lengkap produk.
- **Ucapan Alur**:
  - Route `GET /products/[slug]`.
  - Load produk + gambar dari Supabase Storage.
  - Quantity selector + add-to-cart button.
- **Data Terpengaruh**: Tabel `products`.
- **Edge Cases**:
  - Stok habis → tombol disabled.
  - Produk dihapus admin → halaman 404.

#### 3.2.3 Kategori
- **Deskripsi**: Pengelompokan produk.
- **Ucapan Alur**:
  - Halaman kategori menampilkan produk dalam kategori.
  - Dropdown filter kategori.
- **Data Terpengaruh**: Tabel `categories`.

### 3.3 Fitur Keranjang Belanja

#### 3.3.1 Tambah ke Keranjang
- **Deskripsi**: Customer dapat menambah produk ke keranjang.
- **Ucapan Alur**:
  - Button `add-to-cart` mengirim POST `/api/cart/items` dengan product_id, quantity.
  - Server validasi stok, hitung subtotal, simpan di session atau Supabase.
- **Data Terpengaruh**: Session atau tabel `cart_items` (user_id).
- **Edge Cases**:
  - Stok kurang → error dengan sisa stok.
  - Produk sudah ada di cart → update quantity.
  - Session expired → cart tetap aman di Supabase.

#### 3.3.2 Perbarui Keranjang
- **Deskripsi**: Customer dapat ubah quantity atau hapus item.
- **Ucapan Alur**:
  - PUT `/api/cart/items/{id}` mengubah quantity.
  - DELETE `/api/cart/items/{id}` menghapus item.
- **Data Terpengaruh**: Session + tabel `cart_items`.
- **Edge Cases**:
  - Quantity > stok → error.
  - Item tidak ditemukan.

#### 3.3.3 Tampilkan Keranjang
- **Deskripsi**: Menampilkan isi keranjang dan total.
- **Ucapan Alur**:
  - GET `/api/cart` → render grid item + subtotal + tombol checkout.
- **Data Terpengaruh**: Session.

### 3.4 Fitur Checkout

#### 3.4.1 Form Alamat
- **Deskripsi**: Customer mengisi alamat pengiriman.
- **Ucapan Alur**:
  - Halaman checkout menampilkan form nama, alamat, telepon.
  - Submit simpan ke session (atau Supabase `orders` dengan status `pending`).
- **Data Terpengaruh**: Session + tabel `orders`.

#### 3.4.2 Hitung Total
- **Deskripsi**: Hitung total otomatis berdasarkan keranjang + ongkir (flat rate).
- **Ucapan Alur**:
  - Server-side hitung harga dari cart + shipping fee.
  - Tampilkan total di checkout dan ringkasan order.
- **Data Terpengaruh**: Session.

#### 3.4.3 Pembayaran Midtrans
- **Deskripsi**: Alihkan ke payment interface Midtrans.
- **Ucapan Alur**:
  - Button `Lanjut ke Pembayaran` → POST `/api/orders/pay` → dapatkan snap_token.
  - Redirect ke Midtrans Snap.
- **Data Terpengaruh**: Tabel `orders`, webhook Midtrans.

#### 3.4.4 Konfirmasi Pembayaran
- **Deskripsi**: Webhook Midtrans diproses dan status order diperbarui.
- **Ucapan Alur**:
  - Route `POST /api/webhook/midtrans`.
  - Verifikasi signature, update status `paid` → `processing`.
  - Kirim email konfirmasi.
- **Data Terpengaruh**: Tabel `orders`.

#### 3.4.5 Status Pesanan Customer
- **Deskripsi**: Customer melihat riwayat dan status pesanan.
- **Ucapan Alur**:
  - GET `/api/orders` → daftar order dengan status.
  - Klik order → detail dengan track status.
- **Data Terpengaruh**: Tabel `orders`.

### 3.5 Fitur Administrasi

#### 3.5.1 CRUD Produk
- **Deskripsi**: Admin dapat buat, edit, hapus produk.
- **Ucapan Alur**:
  - Route `/admin/products`.
  - Form untuk name, price, stock, category, image.
  - Submit ke route handler yang simpan ke Supabase.
- **Data Terpengaruh**: Tabel `products`.

#### 3.5.2 Kelola Pesanan
- **Deskripsi**: Admin melihat dan ubah status pesanan.
- **Ucapan Alur**:
  - Tabel order dengan kolom status.
  - Tombol ubah status (pending → processing → shipped).
- **Data Terpengaruh**: Tabel `orders`.

### 3.6 Fitur Tambahan (P1)

#### 3.6.1 Wishlist
- **Deskripsi**: Customer dapat simpan produk favorit.
- **Ucapan Alur**: Tombol heart di detail produk → POST wishlist.

#### 3.6.2 Rating Produk
- **Deskripsi**: Customer memberikan rating dan review.
- **Ucapan Alur**: Form di detail produk.

#### 3.6.3 Notifikasi Email
- **Deskripsi**: Kirim email saat order status berubah.
- **Ucapan Alur**: Trigger Supabase function atau cron.

## 4. Data Model

### 4.1 Tabel `products` (ringkas)
| Kolom | Tipe | Deskripsi |
|-------|------|-----------|
| id | uuid | PK |
| category_id | uuid | FK |
| name | text | Wajib |
| price | bigint | Wajib >0 |
| stock | integer | Wajib >=0 |
| status | enum | active/draft/archived |

### 4.2 Tabel `orders` & `order_items`
| Kolom | Tipe | Deskripsi |
|-------|------|-----------|
| orders.id | uuid | PK |
| orders.status | enum | pending/paid/... |
| orders.total_amount | bigint | Wajib |
| order_items.product_id | uuid | FK |
| order_items.quantity | integer | Wajib |

### 4.3 Tabel `profiles`
| Kolom | Tipe | Deskripsi |
|-------|------|-----------|
| id | uuid | PK |
| full_name | text | Wajib |
| role | enum | customer/admin |

## 5. API Specifications

### 5.1 Endpoints Utama
| Method | Path | Deskripsi |
|--------|------|-----------|
| GET | /api/products | List produk aktif |
| GET | /api/products/[slug] | Detail produk |
| POST | /api/cart/items | Tambah item cart |
| PUT | /api/cart/items/[id] | Update quantity |
| DELETE | /api/cart/items/[id] | Hapus item |
| POST | /api/orders/pay | Buat order + payment token |
| POST | /api/webhook/midtrans | Proses webhook Midtrans |
| GET | /api/orders | List order customer |
| GET | /api/admin/products | List produk admin |
| PATCH | /api/admin/orders/[id] | Update status order |

Semua endpoint menggunakan `auth: true` kecuali publik (katalog).

## 6. Acceptance Criteria

### 6.1 Autentikasi
- Register berhasil → akun aktif.
- Login dengan credential benar → session tersimpan.
- Reset password → email dikirim.

### 6.2 Katalog
- Hanya produk `active` yang ditampilkan.
- Filter kategori dan search berfungsi.
- Detail produk menampilkan stok aktual.

### 6.3 Keranjang
- Tambah item → jumlah di keranjang bertambah.
- Hapus item → jumlah berkurang.
- Total dihitung server-side.

### 6.4 Checkout
- Alamat tervalidasi (minimal field).
- Pembayaran Midtrans → status order `paid`.
- Webhook idempotent (proses hanya sekali).

### 6.5 Administrasi
- Hanya admin dapat CRUD produk dan ubah status order.
- Perubahan status dicatat dengan timestamp.

## 7. Edge Cases

| Kasus | Penanganan |
|-------|------------|
| Stok habis saat checkout | Tolak checkout atau kurangi quantity |
| Payment Midtrans expire | Update status `expired` |
| Produk dihapus admin saat di keranjang | Hapus item atau tolak checkout |
| Multiple tab open | Session tidak boleh dihapus secara sembarangan |
| Hook webhook duplikat | Idempotent dengan order_number |

## 8. Testing

- Unit test untuk route handler (Supabase mock).
- Integration test untuk cart flow.
- E2E test untuk checkout end-to-end di browser.
- Acceptance criteria harus dicakup oleh test.
